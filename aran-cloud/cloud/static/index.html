Three steps, one call.

        
Create a workspace, add the call on your server before you write, and watch the first event arrive in the dashboard. If Aran cannot be reached, store nothing.

      

      

        
Get an API key
You receive an admin key once and a read-only dashboard key. Mint narrower keys for your app server and your compliance officer.

        
Add one call
Call protectFields or /v1/protect on the server. Store the tokens, never the originals.

        
Watch it arrive
Every protected value, sink, reveal and erasure receipt is counted from real calls.

      

      

        

          
          
          
          
        

        
import { Aran } from '@aran/sdk';

const aran = new Aran({ apiKey: process.env.ARAN_APP_KEY!, baseUrl: process.env.ARAN_BASE_URL! });

// on the server, before you write
const tokens = await aran.protectFields({
  fields: { name, mobile, aadhaar },
  customerRef: 'CUS-000123', purpose: 'KYC', sink: 'kyc-archive',
}); // throws if anything is left unprotected: store nothing
await db.insert(customers).values({ customerRef: 'CUS-000123', ...tokens });

        
import os, requests

r = requests.post(f"{os.environ['ARAN_BASE_URL']}/v1/protect", timeout=4,
    headers={"X-API-Key": os.environ["ARAN_APP_KEY"]},
    json={"text": f"Aadhaar {aadhaar}", "customer_ref": "CUS-000123",
          "purpose": "KYC", "sink": "kyc-archive"})
r.raise_for_status()           # fail closed: store nothing if this raises
safe_text = r.json()["after"]  # tokens, not the original values

        
curl -sS -X POST "$ARAN_BASE_URL/v1/protect" \
  -H "X-API-Key: $ARAN_APP_KEY" -H 'Content-Type: application/json' \
  -d '{"text":"Aadhaar 341777631706","customer_ref":"CUS-000123","purpose":"KYC","sink":"kyc-archive"}'

Honest limits.

        
Your application server sees the raw value briefly before calling Aran. Aran makes sure it is not stored or shared downstream in plaintext.

      

      
    
        
  • Detection of identifiers with a checksum is reliable; detection of names is statistical and can miss one. Every response says which values were protected.
    • 
        
  • Names become one-way pseudonyms. They cannot be revealed later.
    • 
        
  • Erasure destroys the key for one customer and one purpose. Tokens issued under other purposes stay readable until you erase those too.
    • 
        
  • An erasure receipt is signed with your workspace’s keys, which Aran holds. It is not signed by your organisation.
    • 
        
  • Backups taken before an erasure are outside Aran’s control. Expire them under your own retention policy.

Obligations Aran helps with

        

        
ObligationWhat Aran provides

        
          
DPDP Act 2023: erasure when consent ends (Section 12)Aran crypto-shreds the purpose key so plaintext cannot be recovered from tokens, and publishes verifiable post-quantum transparency receipts.

          
DPDP Act 2023: security safeguardsIdentifiers are tokenised before they are stored or shared. This is one technical safeguard, not the whole set.

          
RBI directions on data handling and auditScoped API keys, a hash-chained log of every reveal, and per-destination tokens that show where a leak came from.

          
CERT-In directions on logs and incidentsRedacted logs and traceable tokens help you scope a leak. Aran does not report incidents for you.
