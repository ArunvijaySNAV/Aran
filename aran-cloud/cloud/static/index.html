Architecture

Deterministic protection at the boundary

Three discrete cryptographic guarantees applied before data reaches databases, logs, or external AI models.

01 / DETECT & ENROLL

Boundary Inspection

Inspects incoming streams across ORMs, network proxies, and prompt endpoints. Automatically classifies Aadhaar, PAN, Card, Mobile, and Name identifiers with high-precision checksum validation.

02 / TOKENIZE & BIND

Checksum-Failing Tokens

Generates format-preserving tokens bound to designated sinks. Verhoeff (Aadhaar) and Luhn (Cards) checksums are inverted so leaked records are provably invalid to any verifier.

03 / ERASE & ATTEST

Post-Quantum Receipts

Customer erasure permanently destroys the customer purpose key under AES-256-GCM. Emits an append-only Merkle receipt signed with dual Ed25519 and ML-DSA-65 algorithms.

Verification

Proof, not promises

Every security guarantee can be validated directly from your terminal and tested against public standards.

Checksum Invalidation

Every 12-digit Aadhaar token generated fails the official Verhoeff check. Every 16-digit card token fails the ISO/IEC 7812 Luhn check. A leaked token cannot impersonate a real citizen identifier.

How to check: Run python research/test_invalidation.py or test any output token on standard Luhn and Verhoeff decoders.

Cryptographic Sink Attribution

Every token is bound to its designated egress sink (e.g. CRM, ANALYTICS, BACKUP). If an unknown token appears in a dark-web dump, Aran traces the exact originating sink and timestamp.

How to check: Use the "Trace a leak" tool in Aran Cloud or send POST /v1/tokens/trace with the leaked token string.

Post-Quantum Verifiable Receipts

When a customer exercises DPDP erasure, the purpose key is shredded and an append-only Merkle receipt is issued with dual Ed25519 and ML-DSA-65 (NIST FIPS 204) signatures.

How to check: Verify receipt signatures offline using the Aran public keys at GET /v1/public-keys.
Boundaries

Honest limits

Clear operational boundaries so security engineers can evaluate where Aran fits in their defense-in-depth architecture.

Does not replace application authorization. Aran protects identifiers and enforces erasure; it does not replace identity access management (IAM), role-based access control, or session tokens.
Pattern recognition applies to structured PII. Deterministic, checksum-failing tokens apply to Aadhaar, PAN, Card, and Mobile numbers. Natural language names are vaulted via keyed hashes.
Persistence Lite is single-worker. The local persistence mode uses dual SQLite WAL databases with table locks; enterprise active-active multi-region clustering requires distributed consensus.
Key destruction is permanent. When a customer purpose key is shredded, vaulted data cannot be recovered by any party, including Aran infrastructure administrators.
