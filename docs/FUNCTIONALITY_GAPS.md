## Bank screens 5 and 6
11. **Login error is not linked to the fields (Screen 5).** `LoginForm.tsx` shows the error in a banner above the form; wiring `aria-describedby` and moving focus is handler logic. Left as is.
12. **Onboarding flight cannot play (Screen 6).** On success `OnboardForm` redirects to the customer page in an effect that is above the first `return` (protected), and the tokens only exist after the server action returns. The Night side shows a static "What happens on submit" description of `lib/domain.onboardCustomer` instead; no tokens are drawn before they exist. A Review step with the real tokens would need the action to return them before redirecting.
13. **Static assets behind the auth middleware (found in Screen 5).** `bank/middleware.ts` (protected) redirects `/fonts/*` to `/login` for signed-out visitors, so the Archivo files failed to decode on login and portal (HTML served as a font). Fixed on the presentation side by bundling the fonts through the CSS (`app/fonts/`, served from `/_next/static`). The middleware matcher itself should also exclude `/fonts`; not changed.
14. **Onboarding focus after Continue (Screen 6).** Focus falls to the page body when step 2 moves to step 3, because the two buttons carry `key="next"` / `key="submit"` so React does not reuse one node for a click that would otherwise also submit. Moving focus to the new step needs handler code. Left as is.
