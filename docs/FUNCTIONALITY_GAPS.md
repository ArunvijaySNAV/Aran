# Functionality gaps found by the design overhaul

Things `DESIGN.md` asks for that the current backend/API/pages cannot supply. Per the freeze rules they are **not built**; each screen is designed with what exists.

| # | What | Why wanted | Screen | Status |
|---|---|---|---|---|
| 1 | The bank has no record of its recent Aran calls (endpoint, sink, redacted payload, latency) | "Aran Inspector" Night drawer (DESIGN.md §12 Tessera Bank) | all bank screens (top bar toggle) | `Inspector` component built and fed only by props; no toggle mounted until a data source exists |
| 2 | Console theme toggle (`console.js`): on load it removes `data-theme` when no theme is stored, and its first press assumes the OS theme | Light (Stock) by default, optional Night | all console pages | **Visual default solved in CSS** (no `prefers-color-scheme` rules, so the console opens Light on a dark OS; verified: body background `rgb(232, 238, 234)`). A static `data-theme="light"` is kept in the markup but the script removes it at load, so it cannot be relied on. Left unchanged: for a visitor whose OS is dark and who never chose a theme, the first press of the toggle sets "light" (no visible change); the second reaches Night |
| 3 | Signup: the "Continue to connect your app" link is gated only by `pointer-events` and `opacity` set by the inline script, so Tab then Enter reaches `/connect` before the "I have saved both keys" box is ticked | A keyboard-proof gate | signup | not changed (script frozen). Mitigation: solid disabled styling, a visible "Tick the box to continue" line, `aria-disabled`. The keys are already in this tab's session storage, so the bypass skips the confirmation only |
| 4 | Connect: the language tabs are built by the inline script without `aria-controls`, `tabpanel`, roving tabindex or arrow keys; "Send a test event" disables the focused button, so keyboard focus drops to the page body and is not restored; the Sent and Stored labels are fixed script strings | Full tab pattern, focus kept on the Send button, clearer labels ("Your app sent", "What your database holds") | connect | not changed (inline script frozen). The empty frame before the first event does use the clearer wording |
| 5 | Dashboard Audit: a vertical chain of short hashes joined by lines, with Verify chain sweeping top to bottom and ending in "Chain intact · N entries" with a foil moment | DESIGN.md section 8.6 | console dashboard, Audit | the tab renders a table plus a banner (DOM built by `dashboard.js`) |
| 6 | Dashboard Trace: tokens highlighted in blue with lines drawn to sink pills and a confidence figure | section 8.7 | console dashboard, Trace | needs script-built markup around each token; the tab shows a ranked bar list and a table |
| 7 | Dashboard Erasure and receipts: shred animation and a certificate with seal slam, foil sweep on verify | section 8.3 | console dashboard, Erasure and receipts | receipts are table rows with Verify / Download buttons; the certificate moment is shown on the landing as a labelled illustration only |
| 8 | Tables under 640 px as labelled cards (DESIGN.md section 7) | phone layout | all dashboard tables | cells carry no per-column labels in the script's markup, so tables scroll sideways inside their own box on phones |
| 9 | "Latest events as token chips" on Overview and the Reveal countdown inline in Audit | section 12.4 | console dashboard, Overview and Audit | the Overview script renders totals, a chart and two ranked lists; it does not load recent events |
